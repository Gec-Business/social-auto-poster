Three Content Modes

Evergreen Content AI-Generated

Monthly batches of 20-30 posts. Claude generates respecting content mix (35% insight, 20% event, 15% social proof, etc.). Lia reviews in ~30 min. Auto-posts daily.

Priority: 0 (base level)

Product Campaigns Time-Bound

SME Programme, AI Service, Tender Compass. 4 urgency phases from awareness to final push. Posts interleaved with evergreen, higher priority.

Priority: 25-100 (by urgency phase)

Newsletters & Articles Service-Lead Written

Service leads write articles. Lia pastes into admin. Claude extracts 2-3 social excerpt posts. Cross-posted to social + sent as email (Graph API).

Priority: 10 (above evergreen)

Event Promotion Arcs Date-Locked

8 posts at fixed offsets: -14d, -10d, -7d, -3d, -1d, event day, +1d, +3d. Auto-generated from event data. Highest priority — these override everything.

Priority: 200 (highest)

Content Pipeline

Evergreen Flow

Lia clicks "Generate Batch" → /api/content/generate-batch → Claude generates 20-30 posts (respecting content mix) → Stored as content_items with review_status='pending' → Lia reviews in admin (approve/reject/edit) — ~30 min → Approved items fed to scheduler → Scheduler places on calendar (active=daily, break=3x/week) → Vercel cron posts at 9 AM Tbilisi

Campaign Flow

Lia creates campaign: name, product, launch_date → System generates posts in 4 urgency phases → Posts get priority > evergreen, interleaved on calendar → Same review flow: Lia approves before posting → Higher-priority posts override evergreen calendar slots

Newsletter Flow

Service lead writes article → sends to Lia → Lia pastes into /admin/content/newsletters → On "Publish": 1. Claude extracts 2-3 social excerpt posts 2. Excerpts enter normal review → schedule → post pipeline 3. Email newsletter via Microsoft Graph API (stubbed until P4)

Event Arc Flow

Event created → System generates 8 posts at fixed offsets: -14d announcement -10d deep-dive -7d spotlight -3d urgency -1d reminder 0d live +1d takeaway +3d gated recording → Highest priority (200) — date-locked, override everything → If event rescheduled → linked posts auto-updated

Slot Allocation Algorithm

For each posting day: 1. Check if campaign/event_arc post claims this slot (priority > 0) 2. If yes → that post gets the slot, evergreen shifts 3. If no → pick evergreen item that best fits weekly content mix target 4. Create posting_schedule rows per platform with staggered times Content mix is a soft constraint — campaigns and events override it.

Build Order — 5 Phases

Phase 1: Foundation 3 days

Goal: DB exists, publisher works, admin shell

  1. Drizzle schema — all 5 tables
  2. Neon connection (src/lib/db.ts)
  3. drizzle-kit push to create tables
  4. Fork social-publisher.ts — adapt to read from DB
  5. Fork linkedin-tokens.ts — Blobs → PG
  6. Fork auth.ts + middleware
  7. Admin layout shell
  8. vercel.json with cron config
Phase 2: Content Generation + Review 3 days

Goal: AI generates content, Lia reviews

  1. AI content generator — Claude API with GEC brand tone
  2. /api/content/generate-batch route
  3. Review queue page with approve/reject/edit
  4. Content detail view with GE/EN toggle
Phase 3: Scheduling + Auto-Posting 3 days

Goal: Approved content posts automatically

  1. Scheduling engine (src/lib/content-scheduler.ts)
  2. /api/cron/social-post route
  3. LinkedIn OAuth routes (fork)
  4. "Post Now" manual posting
  5. Test full pipeline: generate → review → schedule → post
Phase 4: Campaigns + Events 3 days

Goal: Product campaigns flow through system

  1. Campaign creation UI + generator
  2. Campaign urgency phase logic (4 phases)
  3. Event arc generator (8-post template)
  4. Priority-based scheduling
Phase 5: Newsletters + Polish 3 days

Goal: Full system operational

  1. Newsletter form + excerpt generator
  2. Full calendar view (monthly grid)
  3. Engagement data fetching (Meta insights)
  4. Failed post retry logic
  5. Mobile responsiveness pass
